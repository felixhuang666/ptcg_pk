# RPG Quest Design

## 1. Overview
The RPG Quest System provides a macro-level container for multi-scene gameplay in "Monster Battle". A Quest groups multiple scenes together and defines the player's entry point (default scene) into that specific quest world.

## 2. Quest Structure
A Quest orchestrates multiple scenes and defines properties specific to the quest instance.

### Table Schema
```sql
create table public.game_quest (
  id integer generated by default as identity not null,
  created_at timestamp with time zone not null default now(),
  name text not null,
  scene_list jsonb null,
  quest_entities jsonb null,
  constraint game_quest_pkey primary key (id)
) TABLESPACE pg_default;
```

### 2.1 scene_list
The `scene_list` is a JSONB array of strings representing the IDs of the scenes included in this quest.

```json
[
  "scene_1",
  "scene_2"
]
```

### 2.2 quest_entities
The `quest_entities` JSONB structure holds metadata for the quest, such as the default scene where a player spawns.

```json
{
  "default_scene_id": "scene_1"
}
```

## 3. Backend API Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/api/quests` | List all quests |
| GET | `/api/quest/{id}` | Get quest by ID |
| POST | `/api/quest` | Create new quest |
| PUT | `/api/quest/{id}` | Update quest |
| DELETE | `/api/quest/{id}` | Delete quest |
| POST | `/api/save_local` | Save quest to local filesystem (along with maps, tilesets, scenes) |
