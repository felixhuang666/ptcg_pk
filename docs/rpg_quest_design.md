# RPG Quest Design

## 1. Overview
In the RPG Mode, 'Quests' act as top-level containers for multi-scene gameplay. A Quest stores a collection of scenes and designates an entry point (default scene) for the player. This architecture allows logically grouping multiple scenes into a cohesive narrative or gameplay segment.

## 2. Quest Data Structure
A Quest is represented by the `game_quest` table and contains references to scenes along with quest-specific entities.

### Table Schema
```sql
CREATE TABLE public.game_quest (
  id integer generated by default as identity not null,
  created_at timestamp with time zone not null default now(),
  name text not null,
  scene_list jsonb null,
  quest_entities jsonb null,
  constraint game_quest_pkey primary key (id)
) TABLESPACE pg_default;
```

### 2.1 scene_list
The `scene_list` is a JSONB array that stores the IDs of all scenes linked to this quest.
```json
[
  "scene_1",
  "scene_2",
  "scene_boss_room"
]
```
*Note: The `/api/quest/{id}` endpoint returns only the scene IDs. To display scene names in UI elements (like dropdowns), the frontend must independently fetch the global scene catalog (`/api/scenes`) and cross-reference these IDs.*

### 2.2 quest_entities
The `quest_entities` JSONB structure holds global quest configurations, most notably the entry point.
```json
{
  "default_scene_id": "scene_1"
}
```
* `default_scene_id`: Defines the scene the player is placed into when the quest is initially selected or loaded in `RpgMode.tsx`.

## 3. UI and Integration

### 3.1 Quest Editor (`src/components/QuestEditor.tsx`)
The Quest Editor is a dedicated UI for composing quests:
*   **Scene Management:** Allows adding existing scenes to the quest's `scene_list` and removing them.
*   **Default Scene Selection:** A dropdown to specify which scene acts as the `default_scene_id`.
*   **Persistence:** Supports both database (Supabase) and local file storage capabilities via REST API endpoints (`POST /api/quest`, `PUT /api/quest/{id}`).

### 3.2 RPG Mode Integration (`src/components/RpgMode.tsx`)
*   **Navigation:** The global header navigation includes a scene dropdown grouped by quest, allowing players to traverse between different scenes linked to their active quest.
*   **Entry Point:** When a player starts a quest, the RPG mode uses the `default_scene_id` to determine which scene data to load first.

## 4. Backend API Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/api/quests` | List all quests |
| GET | `/api/quest/{id}` | Get quest by ID |
| POST | `/api/quest` | Create new quest |
| PUT | `/api/quest/{id}` | Update quest |
| DELETE | `/api/quest/{id}` | Delete quest |
