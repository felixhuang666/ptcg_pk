# RPG Quest Design

## 1. Overview
The RPG Mode uses 'Quests' as top-level containers for multi-scene gameplay. A Quest stores a collection of scenes (`scene_list`) and designates a `default_scene_id` which acts as the player's entry point when a quest is selected in RpgMode.

## 2. Structure
### Table Schema
```sql
create table public.game_quest (
  id integer generated by default as identity not null,
  created_at timestamp with time zone not null default now(),
  name text not null,
  scene_list jsonb null,
  quest_entities jsonb null,
  constraint game_quest_pkey primary key (id)
) TABLESPACE pg_default;
```

### 2.1 scene_list
The `scene_list` is a JSONB array that defines the list of scene ids.

```json
[
  "scene_1",
  "scene_2"
]
```

### 2.2 quest_entities
The `quest_entities` JSONB structure holds instances of quest related properties such as `default_scene_id`.

```json
{
  "default_scene_id": "scene_1"
}
```

## 3. Backend API Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/api/quests` | List all quests |
| GET | `/api/quest/{id}` | Get quest by ID |
| POST | `/api/quest` | Create new quest |
| PUT | `/api/quest/{id}` | Update quest |
| DELETE | `/api/quest/{id}` | Delete quest |
