# RPG Quest Design

## 1. Overview
The RPG Mode uses 'Quests' as top-level containers for multi-scene gameplay. A Quest stores a collection of scenes and designates a `default_scene_id` which acts as the player's entry point when a quest is selected in RpgMode.

## 2. Quest Structure
A Quest is a container that organizes multiple scenes and defines the entry point for the player.

### Table Schema
```sql
create table public.game_quest (
  id integer generated by default as identity not null,
  created_at timestamp with time zone not null default now(),
  name text not null,
  scene_list jsonb null,
  default_scene_id text null,
  constraint game_quest_pkey primary key (id)
) TABLESPACE pg_default;
```

### 2.1 scene_list
The `scene_list` is a JSON array of strings containing the IDs of scenes that are part of this quest.

```json
{
  "scene_list": [
    "scene_1",
    "scene_2",
    "scene_3"
  ]
}
```

### 2.2 default_scene_id
The `default_scene_id` specifies the ID of the scene that should be loaded initially when a player enters this quest.

## 3. Data Persistence
- Game data can be loaded from Supabase at startup.
- Falls back to local defaults if Supabase is unavailable.
- Local JSON fallbacks exist in `dist/assets/game_quest/` and `public/assets/game_quest/`.

## 4. UI/UX (Quest Editor)
The Quest Editor (`src/components/QuestEditor.tsx`) allows designers to:
- Create, rename, and delete quests.
- Add and remove scenes from a quest's `scene_list`.
- Set a scene as the `default_scene_id`.
- Save quests to the database or as local JSON files.

## 5. UI/UX (RPG Mode)
In RPG Mode (`src/components/RpgMode.tsx`):
- A dropdown selector allows players to select a quest.
- When switching quests, the scene list reloads to only show scenes within the selected quest.
- The player's last active quest and scene are persisted to the backend. Upon re-entering RPG Mode, the player is restored to their previous quest and scene. If none is found, the system falls back to the default quest.
