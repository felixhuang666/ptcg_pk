# RPG Quest System Design

## 1. Overview
The RPG mode uses 'Quests' as top-level containers for multi-scene gameplay. A Quest stores a collection of scenes (`scene_list`) and designates a `default_scene_id` which acts as the player's entry point when a quest is selected in RpgMode.

## 2. Quest Structure

### Table Schema
```sql
create table public.game_quest (
  id integer generated by default as identity not null,
  created_at timestamp with time zone not null default now(),
  name text not null,
  scene_list jsonb null,
  quest_entities jsonb null,
  constraint game_quest_pkey primary key (id)
) TABLESPACE pg_default;
```

### 2.1 scene_list
The `scene_list` is a JSONB array that defines the collection of scene IDs associated with the quest. The frontend must independently fetch a global scene catalog to cross-reference and display actual scene names.

```json
{
  "scene_list": [
    "scene_1",
    "scene_2"
  ]
}
```

### 2.2 quest_entities
The `quest_entities` JSONB structure holds quest-specific configuration and state, including the `default_scene_id` which acts as the initial entry point.

```json
{
  "quest_entities": {
    "default_scene_id": "scene_1"
  }
}
```

## 3. Backend API Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/api/quests` | List all quests |
| GET | `/api/quest/{id}` | Get quest by ID |
| POST | `/api/quest` | Create new quest |
| PUT | `/api/quest/{id}` | Update quest |
| DELETE | `/api/quest/{id}` | Delete quest |

## 4. Player Quest State Persistence
The player's active quest in RPG Mode is maintained across sessions using the `/api/user/location` endpoint, which updates the `quest_id` column in the `game_player_data` table alongside their scene and position coordinates.

## 5. Local Asset Cache
Quest data persistence uses a multi-layered approach involving the Supabase database, local `.json` file assets, and an in-memory cache (`in_memory_quests` in `backend/main.py`) that must be kept synchronized when quests are saved locally via the `/api/save_local` endpoint.
