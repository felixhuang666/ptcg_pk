# RPG Quest System Design

## 1. Overview
The RPG Quest System is a top-level container for multi-scene gameplay within "Monster Battle". A Quest stores a collection of scenes and designates an entry point which acts as the player's initial spawn location when the quest is selected in RpgMode.

## 2. Quest Structure
A Quest is a logical grouping of RPG Scenes. It is saved in the database in the `game_quest` table and as local JSON files.

### Table Schema (Assumed based on endpoints)
```sql
create table public.game_quest (
  id integer generated by default as identity not null,
  created_at timestamp with time zone not null default now(),
  name text not null,
  scene_list jsonb null,
  default_scene_id text null,
  constraint game_quest_pkey primary key (id)
) TABLESPACE pg_default;
```

### JSON Structure
```json
{
  "id": 1,
  "name": "My First Quest",
  "scene_list": ["scene_1", "scene_2"],
  "default_scene_id": "scene_1"
}
```

## 3. Data Persistence
Quest data uses a multi-layered approach:
1. **Supabase Database**: Uses the `game_quest` table.
2. **Local File Storage**: Saves quests as `.json` files in `public/assets/game_quest/` and `dist/assets/game_quest/`.
3. **In-Memory Cache**: Uses `in_memory_quests` dict in `backend/main.py` which is kept synchronized when saving locally via `/api/save_local`.

## 4. Backend API Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/api/quests` | List all quests (DB, Local, Memory) |
| GET | `/api/quest/{id}` | Get quest by ID |
| POST | `/api/quest` | Create new quest |
| PUT | `/api/quest/{id}` | Update quest |
| DELETE | `/api/quest/{id}` | Delete quest (DB, Local, Memory) |
| POST | `/api/save_local` | Save quest data to local JSON assets |

## 5. Quest Player Location (RpgMode)
The player's active quest in RPG Mode is maintained across sessions using the `/api/user/location` endpoint. This updates the `quest_id`, `map_id` (scene id), `pos_x`, and `pos_y` in the user's session data.
